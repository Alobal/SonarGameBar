# SonarGameBar v2.0 计划

## 版本目标

v2.0 的目标是把第一版可用的混音小组件打磨成更可靠的日常工具：

- 检测并展示当前实际可用的 Sonar 通道；
- 让小组件不只停留在前三个控制项；
- 减少轮询带来的手感摩擦和连接意外；
- 改善构建、测试和发布流程，使项目更适合公开维护。

这个版本仍然聚焦 Xbox Game Bar 使用场景，不做通用的 SteelSeries GG 替代品。

## 优先主题

### 1. 动态 Sonar 混音模型

v1 硬编码了 master、game、chat render 和 ChatMix。v2 应让 `SonarGameBar.Core` 根据 Sonar 当前的 `volumeSettings` 响应构建混音模型。

计划工作：

- 展示 Sonar 返回的所有 classic 模式通道，包括 media、aux 和 chat capture；
- 为已知通道保留稳定内部 ID，同时允许未来未知通道安全展示；
- 返回通道显示名、音量、静音状态、模式支持情况以及是否可控制；
- 将通道校验从固定白名单改为“已发现通道”白名单；
- 尽量保持 v1 命令名兼容。

验收标准：

- 小组件可以控制 Sonar 响应中可见的每个受支持 classic 模式通道；
- 不支持或缺失的通道会被隐藏或禁用，而不是导致致命错误；
- GG/Sonar 重启后，通道列表能刷新，不需要重装小组件。

### 2. 活跃音轨检测

v2 最有价值的功能，是帮助用户看见当前正在使用哪条 Sonar 音轨。

计划调研：

- 优先检查 Sonar 本地接口是否暴露通道活动、路由或设备元数据；
- 如果 Sonar 暴露的数据不足，则通过 full-trust Bridge 检查 Windows Core Audio 会话和 Sonar 虚拟设备；
- 将 gaming、chat、media、aux 等设备映射到 Sonar 混音通道；
- 在当前有音频活动的行上显示“活跃”标记；
- 可选：自动展开或将活跃通道排序到顶部。

验收标准：

- 当音频通过 Sonar 虚拟设备播放时，对应通道有明确可见标记；
- 检测过程不会把进程名或音频会话数据发送到本机外；
- 活跃检测失败时，不影响手动混音控制。

### 3. Streamer/classic 模式兼容

v1 会在 Sonar 不处于 classic 模式时提示。v2 应让这个状态更清晰，并为 streamer 模式支持留出路径。

计划工作：

- 将当前 Sonar 模式作为一等状态展示；
- 保持 classic 模式完整支持；
- 在安全 feature flag 后探测 streamer 模式响应结构；
- 禁用当前模式下无法安全映射的控制项；
- 为模式不匹配提供更清晰的错误提示。

验收标准：

- classic 模式仍是默认支持路径；
- streamer 模式不会意外收到 classic 模式写入；
- 用户能从小组件里理解某个控制项为什么不可用。

### 4. 小组件交互打磨

v1 UI 已经可用。v2 应在固定到游戏画面上时更稳定、更顺手。

计划工作：

- 从数据渲染通道行，而不是硬编码 XAML 块；
- 增加快捷操作：ChatMix 居中、偏向游戏、偏向聊天、静音聊天；
- 增加紧凑和展开两种布局状态；
- 改善断线、加载、禁用状态；
- GG 关闭时避免重复刷屏式提示；
- 滑块写入采用乐观 UI，失败时回滚；
- 确保所有文字在较窄 Game Bar 小组件尺寸下不溢出。

验收标准：

- 在最小可用小组件尺寸下没有文字重叠；
- 拖动滑块时反馈即时，不会被轮询“抢回去”；
- 刷新/重连入口清楚，但不打扰。

### 5. Bridge 可靠性和协议版本

Bridge 是正确的架构方向，但 v2 应让协议更明确。

计划工作：

- 增加协议版本和 `capabilities` 响应；
- 增加请求 ID 和结构化错误码；
- 为每个 Sonar 请求增加取消和超时处理；
- 防止多个 Bridge 实例竞争；
- 将隐私安全的诊断信息保存在 `%LOCALAPPDATA%\SonarGameBar`；
- 增加 `diagnose` 命令，用于生成支持信息。

验收标准：

- 小组件能检测不兼容 Bridge，并显示有用提示；
- 小组件关闭后 Bridge 能干净退出；
- 诊断信息不包含用户名、电脑名、令牌、证书或完整无关进程列表。

### 6. 测试和发布加固

v2 应让项目发布到 GitHub 后更容易维护。

计划工作：

- 为 Sonar JSON 解析、通道发现和本机回环 URI 校验增加单元测试；
- 增加假的 Sonar HTTP 服务，用于集成风格测试；
- 增加 Bridge 协议成功和错误响应测试；
- 将 GitHub Actions 从隐私审计扩展到构建/测试；
- 增加版本 bump 脚本，同步 manifest、包和文档版本；
- 继续忽略生成包、证书、日志、符号文件和构建输出。

验收标准：

- Core 解析行为可以更放心地修改；
- CI 能在发布前发现构建失败；
- 公开发布时不需要手动改多个位置的版本号。

## 建议 v2.0 范围

必须有：

- classic 模式动态通道发现；
- 在小组件中展示所有 classic 模式 Sonar 输出通道；
- 活跃通道检测技术验证，并在可行时至少提供可见的活跃通道标记；
- 协议版本和 capabilities；
- Core 解析和 URI 安全测试；
- 构建/测试 GitHub Action。

应该有：

- 紧凑/展开 UI；
- ChatMix 快捷操作；
- 更好的模式和断线状态；
- 隐私安全的诊断命令。

可以有：

- streamer 模式只读预览；
- 每通道自定义标签；
- 保存小组件布局偏好；
- 发布打包辅助脚本。

v2.0 不计划：

- 替代 SteelSeries GG 路由 UI；
- 云同步；
- Microsoft Store 分发；
- 在 Xbox Game Bar 外提供全局热键，除非找到安全的打包应用路径。

## 建议里程碑顺序

### 里程碑 1：模型和测试

1. 为当前 `volumeSettings/classic`、`chatMix` 和 `mode` 解析增加 Core 测试。
2. 用发现式混音模型替换固定通道解析。
3. 先让现有 v1 UI 从新模型取数，降低风险。

### 里程碑 2：动态 UI

1. 动态渲染通道行。
2. 增加 media、aux 和 chat capture 支持。
3. 改善断线、不支持模式和禁用控制状态。

### 里程碑 3：活跃音轨检测

1. 探索 Sonar 本地接口中的路由/活动元数据。
2. 如有需要，在 Bridge 中原型验证 Windows Core Audio 兜底方案。
3. 在小组件中展示活跃标记。

### 里程碑 4：打磨和发布

1. 增加协议版本和 capabilities。
2. 增加诊断和 CI 构建/测试。
3. 更新文档并准备 v2.0 发布说明。

## 主要风险

- SteelSeries 本地接口未公开文档化，可能变化。
- UWP 加 full-trust 打包链路在构建改动中容易被破坏。
- Windows Core Audio 活跃检测可能需要谨慎处理 COM interop，而且不一定能为所有用户干净映射。
- 控制项增多后，固定在游戏画面上的小组件可能变得拥挤，所以紧凑布局要尽早设计。

## 当前实现状态

已完成：

- classic 模式动态通道发现；
- 媒体、Aux、chat capture 等 Sonar 返回通道的动态 UI；
- 基于 Windows 音频端点峰值的活跃通道标记；
- ChatMix 快捷操作和紧凑布局；
- Core 解析与本机地址安全测试；
- GitHub Actions 构建、测试和公开发布审计。

仍需后续验证和打磨：

- 在更多 SteelSeries GG / Sonar 版本上确认接口响应结构；
- 验证不同语言或设备名下的 Sonar 虚拟设备映射；
- 探索 streamer 模式只读预览；
- 增加更完整的 Bridge 协议版本与诊断命令。

## 第一阶段实现建议

先从测试和动态通道发现开始。这会让后续功能更安全，也能直接为缺失的“自动音轨检测”打底，而不会过早押注某一种检测方法。
